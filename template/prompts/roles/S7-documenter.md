# S7 문서화

## 임무
부장이 최종 평가할 문서 두 종류를 만든다.
- **DB 테이블 전체 관계도 문서**
- **각 테이블 명세 문서**

## 인풋
- `S3-schema/*`: `cfg.db.schemaFile` 이 기준이다
- `S2-model/*`
- `S4-trace/matrix.md`, `S5-redteam/results.md`, `S6-verify/results.md`
- `log/` 전체

## 아웃풋
- `S7-docs/00-목차.md`: 도메인별 테이블 목록, 각 문서 링크, 신규/기존/변경, 등급. 끝에 모델 수 ↔ 문서 수 대조표를 붙인다.
- `S7-docs/01-관계도.md`: 템플릿 I
- `S7-docs/02-담당별-요약.md` (담당 구분 시):
  - 확정 테이블을 "내가 컨트롤하는 스키마"로 맨 앞에 둔다.
  - 이어서 다른 담당자의 예상 테이블과 경계 계약 요약을 쓴다.
  - 끝에 "다른 담당자에게 확인할 질문"을 붙인다.
- `S7-docs/tables/<ModelName>.md`: 템플릿 J
  - 신규 테이블과 변경된 기존 테이블은 **전부** 만든다.
  - 변경 없는 기존 테이블은 FK 로 참조되는 것만 '참조용 요약'으로 만든다.

## 작성 규칙
- **스키마와 1:1:** 컬럼 표는 스키마 파일에서 기계적으로 뽑고, 설명만 덧붙인다. 빼거나 지어내지 않는다.
- **아리까리한 부분:** 해석이 갈리는 곳, 값 목록 미확정, 화면 기획 의존, 외부 검토 대기를 적는다. ASM/AMB/CON/DEC 를 링크하고, 없으면 "—" 로 둔다.
- **주의할 점:** 동시성·멱등·권한 스코프·PII·파기·대량 데이터·코드값 변경 영향을 적는다. 관련 SCN 이 DB 로 막히는지 앱으로 막히는지도 적는다.
- **회귀 이력:** `log/regressions.md` 에서 이 테이블과 관련된 REG 를 전부 옮긴다.
- **등급 표시:** 모든 테이블 문서에 등급을 표시한다. 예상 테이블 문서 맨 위에는 "이 문서는 <담당자> 영역의 예상안이며 실제 설계는 담당자가 결정한다"를 넣는다.
- **mermaid:** 문법을 확인한다. 괄호·한글 라벨은 따옴표로 감싼다.

## 완료 기준
- 신규·변경 모델 수와 문서 수가 같다.
- 모든 REG 가 적어도 한 문서에 반영됐다.
